# AGENTS.md: canonical agent guide

This file is the single source of truth for autonomous systems operating in this
repository. Vendor files (`CLAUDE.md`, `GEMINI.md`, `.cursorrules`) are stubs
pointing here. If any of them says more than three lines, that is a bug.

## 1. Purpose

`atlas` is a **specification suite** (`type: content.spec`). The prose
in `spec/` is the product; everything else validates, scaffolds, or enforces it.
The repository is self-hosting: it must always pass its own compliance checks
(`atlas check`).

Unfamiliar with a term used here? [`docs/reference/glossary.md`](docs/reference/glossary.md).

## 2. Map

```

                            does is a function here; the CLI only parses, renders,
                            and returns exit codes.
  core/                     domain logic: manifests, specs, workstreams, library,
                            template mirroring, design tokens, and the compliance
                            registry (add a gate by registering one, not by
                            editing a shell script)

                            markdown, highlight, theme, layout, search, builder

                            parser, never hand-edit it.

                            human output in each command so they cannot drift

                            Each carries YAML front matter (id, version, status,
                            rule_prefixes, companions). Read that, not the prose,
                            when you need to know what a spec covers.
  workspace.md              filesystem organization and lifecycle
  project.md                repository-level standard (defines this repo's rules)

  project-checklist.md      quality gates per maturity profile

  presentation.md           forge metadata, README composition, visual identity

  workstream.md             rules for work/ (W-I1..W-I6, W-01..W-20)
  schemas/*.schema.json     machine-readable manifest schemas; enum values must
                            stay in sync with the prose (CI checks)

                            initiative, nine numbered sections each plus a README
                            and a manifest. work/README.md and work/index.yaml are
                            GENERATED by `atlas work sync`. Read them, never edit
                            them. Start any work task by reading work/index.yaml.

                            typefaces, media. The set is CLOSED. Prompts are
                            GENERATED by scripts/generate_prompts.py. Edit the

                            the source, not the mirror (see §5). It depends on the

                            the tooling.

  guides/                   install, adoption, project creation, work management
  reference/                glossary, conventions, rule-ids, versioning, CLI

                            consistency, spec metadata, prompt and workstream

                            a bare checkout. NO LOGIC LIVES HERE.
```

## 3. Commands

```bash
pip install -e ".[dev]"                # the CLI plus test dependencies
python -m pytest tests/ -q             # full test suite

atlas check                            # every compliance gate (start here)
atlas doctor                           # environment + repository diagnostics
atlas status                           # what this repository is, at a glance
atlas validate <manifest>              # validate one manifest against its schema
atlas init <name> <dest>               # scaffold a compliant repository
atlas work new|list|show|sync|validate|archive
atlas spec list|show|rules             # read the standards, cite their rules
atlas prompt list|show|search          # the reusable request library
atlas library list|check               # shared assets
atlas template check|sync              # the starter scaffold and its mirror
atlas site build|serve|clean           # the documentation site
atlas completion bash|zsh|fish         # shell completion

python scripts/generate_prompts.py     # regenerate library/prompts/ from source
python scripts/build_assets.py         # regenerate the brand SVGs
scripts/atlas <command>                # any of the above, with no install
```

Every command accepts `--json` for machine-readable output and `-C <dir>` to
operate on another repository. Exit codes: `0` ok, `1` violations found, `2`
bad usage, `3` not found, `4` not an Atlas repository. **Agents should prefer
`--json`**: the human rendering is not a stable contract; the JSON is.

All commands run from anywhere inside the repository. There is no build step.

## 4. Conventions

Full detail in [`docs/reference/conventions.md`](docs/reference/conventions.md).
The short version:

- Commits: **Conventional Commits** (`feat:`, `fix:`, `docs:`, `chore:`, `spec:`,
  `test:`, `ci:`, `refactor:`). `spec:` is the local type for normative changes
  to `spec/*`; those require a version discussion.
- Branches: `type/short-description` (for example `docs/clarify-waivers`).
- Markdown: `kebab-case.md`. Python: `snake_case.py`. Shell: `kebab-case.sh`.
  ADRs: `NNNN-short-title.md`. Workstreams: `NN_slug`.
- One `h1` per document, naming the document rather than the file.
- SemVer for the suite (`v1.0.0`), separate from the manifest contract version
  (`project/1.0`). See [`docs/reference/versioning.md`](docs/reference/versioning.md).

## 5. Constraints: what agents must NOT do

- **Never edit a generated file.** The full list is in
  [`docs/reference/conventions.md`](docs/reference/conventions.md#generated-files).
  It includes `work/README.md`, `work/index.yaml`, everything under `library/prompts/`,
  three files under `template/`, and all of `site/`. Every one is drift-checked
  in CI, so editing one turns the build red rather than silently working.
- **Never edit accepted ADRs** in `docs/decisions/`: supersede with a new one.
- **Never change normative text in `spec/*.md`** without updating, in the same
  change-set: the matching JSON Schema in `spec/schemas/`, the `version:` field
  in the spec's front matter, and `CHANGELOG.md`. CI enforces the schema half.
- **Prompt edits go through the generator.** Destructive-operation prompts keep
  their plan-before-act gates (L-04).
- **Template edits go through `atlas template sync`.** Edit `work/_template/` or
  `spec/schemas/workstream.schema.json`, then run the sync. The mirror direction
  is one-way and never reversed.
- **Keep `metadata.description` identical** across `project.yaml`,
  `.github/settings.yml`, and the README title line. CI checks the first two;
  reviewers check the third.
- **Stay inside your workstream.** A workstream owns its directory; do not write
  into another one (W-I4). Cross-workstream relationships are declared in
  `workstream.yaml` (`depends_on`, `blocks`, `relates_to`).
- **Record handoffs and logs** in `08_agents/` when work passes between agents;
  a handoff that exists only in a chat log did not happen (W-16).
- **Never mark a workstream `done` without evidence** for every acceptance
  criterion (W-I5). `atlas work validate` enforces this.
- **Never add root entries.** The root is a closed set enforced by
  `atlas check --only root-closed-set`. New needs go inside an existing role
  directory or through an ADR.
- **Never hand-edit `docs/reference/cli.md`.** It is generated from the argument
  parser by `atlas site build --write-reference`, and CI fails if the committed
  copy differs. Change `src/atlas/cli/` and regenerate.
- **Never put logic in `scripts/`.** Those files are wrappers so a bare checkout
  works without an install. Behavior belongs in `src/atlas/`.
- **Never put a count in prose unless something checks it.** Four wrong counts
  were shipped in the draft this repository replaced.
- Vendor agent files are stubs; do not add content to them.
- No secrets exist in this repository and none may be added; manifests hold
  authority, never credentials (ADMIN I-6).

## 6. Definition of Done

A change is done when `pytest` is green, `atlas check` passes, `CHANGELOG.md`
has an entry under `Unreleased`, affected docs and guides are updated, the
generated CLI reference is current (`atlas site build --write-reference` leaves
no diff), and (for spec changes) the schemas match the prose.
