# Repository design

## What this repository is

A `content.spec` project: the prose in `spec/` is the product; everything else
validates, scaffolds, or enforces it. The single load-bearing design decision
is **self-hosting** (ADR-0001): the repository must always pass its own
standard, because a standards repo that violates its own standard has already
lost the argument.

## Source root

`spec/project.md` permits "the language's idiomatic equivalent" of `src/`. For a
specification suite, the idiom is `spec/`: implementations cite it, the
distinguishing test for `content.spec` in the Matrix. Schemas live inside it
(`spec/schemas/`) because they are normative artifacts of the same product,
versioned with the prose they encode (ADR-0004).

## How truth is kept single-sourced

| Fact | Home | Everything else |
|---|---|---|
| Normative rules | `spec/*.md` (eight standards) | links; front matter carries the citable metadata |
| What work is happening | `work/NN_slug/` Markdown | `work/README.md` + `work/index.yaml` generated by `atlas work`; the site is generated from both |
| Reusable requests | `scripts/generate_prompts.py` (generator) | `library/prompts/` files + `index.yaml` + README are emitted; tests enforce sync |
| The scaffold's copy of the work system | `atlas work`, `work/_template/`, `spec/schemas/workstream.schema.json` | `template/` mirrors them via `atlas template sync`; `--check` runs in CI |
| Terms of art | `docs/reference/glossary.md` | every other document links rather than redefines |
| Rule identifier namespaces | each spec's front matter | `docs/reference/rule-ids.md` registers them; tests assert agreement |
| Forge metadata | `project.yaml metadata:` | `.github/settings.yml` mirrors it (CI drift check), README title restates it |
| Visual identity | `assets/*.svg` (hand-authored, diffable) | README embeds; template inherits per P-11 |
| Machine-readable enums | `spec/schemas/*.json` | CI-checked against prose (`tests/test_spec_consistency.py`) |
| Classification & status | `project.yaml` | README badges/Status mirror it |
| Why the repo is shaped this way | `docs/decisions/` | this file links to them |
| How to operate here | `AGENTS.md` | vendor stubs point at it |

## Enforcement chain

```
spec prose ──consistency tests──▶ schemas ──validate.py──▶ manifests
     ├───────────── check-compliance.sh ─────────────▶ root, docs, presentation
     └───────────── work.py validate ────────────────▶ workstreams, tasks, graph
                              └──── ci.yml runs all of it on every PR ────┘

work/*.md (canonical) ──atlas work sync──▶ dashboard + index ──atlas site build──▶ site/
```

A rule exists in exactly one of three strengths, deliberately: schema-enforced
(hard fail), script-checked (hard fail), or prose-only (reviewer judgment,
the 🧭 items). Anything promoted from prose to check is a `spec:` commit.

## Sanctioned root extensions

Three product surfaces sit at the root beyond the standard's base set, each
by deliberate revision rather than accretion (ADR-0002):

- `template/`: the scaffold consumers copy; kept at root because it is a
  primary user-facing artifact and the "Use this template" flow depends on it.
- `library/prompts/`: the request-prompt catalog; generated from one source so the
  files, index, and README cannot disagree (ADR-0003).
- `assets/`: brand and diagram SVGs plus `design/tokens.yaml`; part of PROJECT
  §9's canonical hierarchy, made mandatory here by the PRESENTATION hero-visual
  requirement.

Everything else at the root is a violation, and `atlas check`
fails on it. Build output is not an exception granted by that list. It is
skipped because git ignores it, so if `site/` ever stops being gitignored the
check starts failing, which is the correct outcome.

## Why `template/` mirrors instead of importing

The obvious way to remove `template/`'s duplication is to make it reference
`../atlas work` and `../spec/schemas/`. That works perfectly here and fails
everywhere else: `template/` exists to be copied *out*, and the moment it leaves,
a relative path to `../spec/` points at nothing.

So the files are real, standalone, and generated. `atlas template sync` is
the one direction of flow, `--check` is the gate, and `atlas work` resolves
its schema from either location so a single file can serve both homes. The
rationale is recorded in
[`work/01_harden-repository-baseline/04_decisions/0001-mirror-rather-than-import.md`](../../work/01_harden-repository-baseline/04_decisions/0001-mirror-rather-than-import.md).

## Directory conventions

Every directory in this repository, and in anything scaffolded from
`template/`: carries the same meaning across the fleet:

| Path | Role | Change cadence |
|---|---|---|
| `spec/` (or `src/`) | the product | deliberate, versioned |
| `tests/` | mirrors the product's topology | with the product |
| `docs/architecture/` | how it is built and why | on structural change |
| `docs/decisions/` | ADRs; append-only, superseded not edited | on decisions |
| `docs/guides/` | task-oriented how-tos | on workflow change |
| `docs/reference/` | generated or verified surface docs | with the surface |
| `examples/` | runnable, CI-verified samples | with the surface |
| `scripts/` | development and maintenance automation | freely |
| `assets/` | brand, diagrams, binary fixtures | rarely |
| `work/` | initiatives: plan, tasks, evidence, agent coordination | continuously |
| `.github/` | CI, templates, forge settings as code | on policy change |
| `template/` | the scaffold consumers copy | via `atlas template sync`, never by hand |
| `library/` | shared assets: prompts, icons, typefaces, media | by pull request; prompts via `generate_prompts.py` |
