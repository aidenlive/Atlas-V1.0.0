## The audit changed the order of work

The plan was to start with `build_site.py`: the largest file, the obvious
target. The audit ([`05_research/`](../../05_research/2026-08-07-tooling-audit.md))
moved it last. `build_site.py` was working and covered by the metadata tests;
`check-compliance.sh` was 90 lines enforcing the repository's central promise
with zero tests and prose output nothing could parse. Starting there is why the
compliance engine became a registry rather than a straight port to Python.

## The `-C` bug was found by a test written for a different reason

`test_outside_a_repository_exits_no_repository` was written to check an exit
code. It failed by returning `0`, because `-C /tmp/empty status` had quietly
operated on the Atlas repository instead. Argparse applies a subparser's
defaults *after* the parent has parsed, so every subparser copy of a global flag
was overwriting the value the root parser had already read. `atlas --json check`
was losing `--json` the same way.

This would have shipped. It produces no error, and the output looks entirely
correct. It is simply about the wrong repository. Anything with a per-parser
default flag is worth checking for this.

## The stylesheet regression argues for the existing tests

Rewriting the stylesheet dropped the `@container content` wide break-out rule.
`test_site_shell_uses_container_queries_for_structure` caught it. That test
looked like design pedantry when it was written; it was the only thing standing
between a rewrite and a silent revert to viewport-driven structure.

## Left deliberately undone

The site's search index ships every page's body truncated to 1400 characters,
which is 125 KB. It is fetched on first open rather than at page load, so most
visits never pay for it. A real inverted index would be smaller and much more
code; if the corpus doubles, revisit: until then this is the right trade.
